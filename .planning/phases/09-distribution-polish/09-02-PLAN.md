Purpose: Satisfies DIST-06 + DIST-07. Without this plan, `brew install` and `cargo install` can't reach yogurt — only the direct GitHub Release tarball download works.
Output: Bootstrapped `jarvisrchen/homebrew-yogurt` repo, extended release workflow with tap + publish jobs, CHANGELOG.md with v0.1.0 entry.
</objective>

<task type="auto">
  <name>Task 2: Extend `.github/workflows/release.yml` with `tap` and `publish` jobs</name>
  <files>.github/workflows/release.yml</files>
  <read_first>.github/workflows/release.yml, docs/superpowers/plans/2026-06-25-yogurt-phase-9-polish-and-distribution.md</read_first>
  <action>
    Append two new jobs to the existing `release.yml` (built in plan 09-01). Do NOT modify the existing `build` and `release` jobs.

    **Job `tap` (needs: release, if: github.event_name == 'push'):**
    - Runs on `ubuntu-latest`. Never runs on dry-run (the `if` guard).
    - Steps:
      1. `actions/download-artifact@v4` with `pattern: yogurt-*, merge-multiple: true`.
      2. Compute per-arch SHA256s from the downloaded `.tar.gz` files: `ARM_SHA=$(shasum -a 256 yogurt-aarch64-apple-darwin.tar.gz | awk '{print $1}')`; same for x86. Set as job outputs.
      3. Resolve version: `echo "version=${GITHUB_REF#refs/tags/v}" >> "$GITHUB_OUTPUT"`.
      4. Checkout the tap repo: `actions/checkout@v4` with `repository: jarvisrchen/homebrew-yogurt`, `path: tap`, `token: ${{ secrets.HOMEBREW_TAP_TOKEN }}`.
      5. Rewrite `tap/Formula/yogurt.rb` using a heredoc that interpolates the resolved version and the two SHAs. The formula body matches the placeholder template but with real values.
      6. Open the PR:
         ```bash
         git config user.name "yogurt-release-bot"
         git config user.email "release-bot@yogurt.local"
         BRANCH="bump-${{ steps.ver.outputs.version }}"
         git checkout -b "$BRANCH"
         git add Formula/yogurt.rb
         git commit -m "yogurt ${{ steps.ver.outputs.version }}"
         git push origin "$BRANCH"
         gh pr create --title "yogurt ${{ steps.ver.outputs.version }}" \
                      --body "Auto-PR from the yogurt release workflow." \
                      --base main --head "$BRANCH"
         ```
         Set `GH_TOKEN: ${{ secrets.HOMEBREW_TAP_TOKEN }}` in env for `gh pr create`.

    **Job `publish` (needs: [release, tap], if: github.event_name == 'push'):**
    - Runs on `ubuntu-latest`. Never runs on dry-run. CRITICAL: `needs: [release, tap]` ensures publish only runs AFTER both the GitHub Release exists AND the tap PR is filed — the publish hygiene rule.
    - Steps:
      1. Checkout main repo.
      2. Install Rust 1.83 via `dtolnay/rust-toolchain@stable`.
      3. Publish, idempotent:
         ```bash
         VER="${GITHUB_REF#refs/tags/v}"
         if cargo search yogurt | grep -q "^yogurt = \"$VER\""; then
           echo "yogurt $VER already published — skipping."
           exit 0
         fi
         cargo publish -p yogurt
         ```
         Env: `CARGO_REGISTRY_TOKEN: ${{ secrets.CRATES_IO_TOKEN }}`.

    VERY IMPORTANT — publish hygiene: do NOT change the `needs:` ordering. The chain is `build → release → tap → publish`. If anyone reorders these (e.g. publishes before release), `brew install` 404s get cached by Homebrew's mirror infrastructure and the bad state outlives the fix.
  </action>
  <verify>
    `yq eval '.jobs.tap.needs' .github/workflows/release.yml` returns `release`. `yq eval '.jobs.publish.needs' .github/workflows/release.yml` returns `[release, tap]` (or an equivalent list representation). `yq eval '.jobs.tap.if' .github/workflows/release.yml` references `github.event_name == 'push'`. Same for `publish`.
  </verify>
  <acceptance_criteria>
    - `release.yml` contains a `tap` job with `needs: release`

    - Both new jobs have `if: github.event_name == 'push'` (so dry-run skips them)
    - `tap` job uses `jarvisrchen/homebrew-yogurt` and `secrets.HOMEBREW_TAP_TOKEN`

  </acceptance_criteria>
  <done>Workflow has both new jobs, ordering enforced, dry-run guards prevent accidents.</done>

2. Create `crates/yogurt-server/src/session.rs` with `pub struct SessionToken(pub String)` and:
   - `pub fn default_token_path() -> anyhow::Result<PathBuf>`: resolves `<home>/.yogurt/session-token` via the `directories` crate (re-use parent-dir creation from storage).
   - `pub fn load_or_create(path: &Path) -> anyhow::Result<SessionToken>`: if path exists, read it (trim whitespace); else generate 32 random bytes via `rand::thread_rng().fill(&mut [u8; 32])`, base64-URL-encode (`base64::engine::general_purpose::URL_SAFE_NO_PAD`), write to path. PART B — WebSocket endpoint (D-20, FOUND-05):

4. Add to `crates/yogurt-server/Cargo.toml` `[dependencies]`: `axum = { workspace = true, features = ["macros", "ws"] }` (enable the `ws` feature). Also `tokio-tungstenite = "0.24"` is NOT needed for this stub — axum's built-in WS is sufficient.
5. Create `crates/yogurt-server/src/ws.rs` exposing `pub async fn ws_handler(...)` — an axum WebSocket upgrade handler that:
   - Extracts `Origin` header; validates against the allowlist `["http://localhost:7878", "http://127.0.0.1:7878"]`. If the bound port is not 7878 (e.g. `--port 17878` in tests), the allowlist is generated dynamically from the bound port — store the bound port in app state too (add `pub bind_port: u16` to a `pub struct AppConfig` that already holds whatever needed). On mismatch, return `StatusCode::FORBIDDEN`.
   - Extracts the session token from EITHER (a) the `?token=` query param OR (b) the `Sec-WebSocket-Protocol` subprotocol header parsed as `yogurt.<token>`. Validates via `SessionToken::validate`. On mismatch, return `StatusCode::FORBIDDEN`.
   - On success, upgrade the connection and echo received messages (Phase 0 stub — real WS payloads land in Phase 3). When unsupported features are blocked (e.g. binary frames), close the connection cleanly.
6. Register `/ws` route in `routes::router`: `.route("/ws", get(crate::ws::ws_handler))`. Make sure this is registered BEFORE the fallback (axum routes always win over fallbacks anyway, but explicit ordering helps readability).
7. Wire app state: app state is now `(Arc<Storage>, Arc<SessionToken>, AppConfig{bind_port})` — bundle into a single `pub struct AppState` and use `Router::with_state` or `Extension` consistently.

PART C — WS auth integration tests:

8. Create `crates/yogurt-server/tests/ws_auth.rs` (add `tokio-tungstenite = "0.24"` to `[dev-dependencies]` for the WS client):
   - `it_rejects_ws_with_bad_origin`: spawn server on a random port (e.g. 17882), attempt WS handshake with `Origin: http://evil.example` → expect connection upgrade failure with HTTP 403.
   - `it_rejects_ws_without_token`: spawn server, attempt WS handshake with correct Origin but no token query param → 403.
   - `it_accepts_ws_with_correct_origin_and_token`: spawn server, read token from the session-token file written during boot, attempt WS handshake with `Origin: http://localhost:<port>` and `?token=<token>` → upgrade succeeds.
   IMPORTANT for tests: use a per-test tempdir for both `~/.yogurt/db.sqlite` AND `~/.yogurt/session-token`. Expose a test-only constructor `Storage::init_at(path)` and `session::load_or_create_at(path)` to avoid clobbering the developer's real `~/.yogurt/`. Pass the override paths into `yogurt_server::run` via a new `RunConfig` struct or by adding test-mode args to `Mode`. Document the approach inline.

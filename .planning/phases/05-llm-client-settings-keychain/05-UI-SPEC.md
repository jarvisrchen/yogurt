# Phase 5 — UI Design Contract

> Visual and interaction contract for the Settings page (Model · Transcription · Audio · General). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Hero pattern:** 212px left sidebar + main content right. Active LLM provider rendered as a 1.5px-blueberry-bordered card with mono BASE URL + MODEL + masked-key-with-last-4 + green "✓ stored" badge. Sidebar footer signals privacy posture with the green matcha "Local-only · on" pill and a JetBrains-Mono caption disclosing where keys/data live.

**Voice rules (PRD §16.1):**
- Warm + editorial + dev-tooly. No exclamation marks. No emoji except the literal glyphs already in the design (`✓`, `→`, `·`, `⌄`).
- Mono captions disclose system facts (`localhost:7878`, `keys → macOS Keychain`, `~/.yogurt/`). Never wrap a path or hostname in prose font.
- "Bring your own key" tone — never apologetic about the user pasting credentials, never marketing-speak.
- The phrase **"Local-only · on"** is canonical. Variants like "Local only", "All local", "Offline mode" are forbidden.

**Masked-key format (load-bearing):**
- Pattern: `••••••••••••••••••••••` (22 bullet chars `U+2022`) + ` ` (one space) + last 4 characters of the key in mono + ` ` + green `✓ stored`.
- Never display more than the last 4 chars. Never log the unmasked key. The masked form is the *only* thing the `GET /api/settings` response ever contains (asserted by test `api_responses_never_include_the_raw_api_key`).
- When the field is editable (Edit mode), swap to a `<input type="password">` with placeholder `paste your key…` and a save button labelled `Save key` (Hanken 600, blueberry); on save, re-mask immediately.

## Interaction Notes (non-token, contract-bearing)

These are not tokens but are part of the visual/behavioral contract checkers must verify:

1. **Sidebar footer pill visibility = privacy-posture signal.** `<LocalOnlyPill on={…} />` is `true` iff *no active LLM provider has a non-localhost base URL* AND *no active STT provider is cloud*. (Computed server-side, returned as a boolean on `GET /api/settings`.) The pill must never lie — if a cloud provider is active, the pill is hidden and the footer collapses to just the mono caption.
2. **Active card is unique per kind.** Exactly one LLM provider has the 1.5px blueberry border at any time. Switching is atomic (D-18 partial unique index). On click of `Set active`, the previously active card demotes to a `<ProviderRow />` and the newly active row promotes to `<ProviderCard />` in the same paint — no intermediate "two-active" flicker.
3. **Masked key never leaks.** Every key field in the UI consumes `api_key_masked` from the API. There is no code path where a raw key is held in React state after save (input is uncontrolled `<input type="password">`, value posted directly to the mutation, then field re-rendered with the new masked value from refetch).
4. **`⌄` glyph on the device dropdown** is the literal Unicode `U+2304` (DOWN ARROWHEAD), not an SVG — matches design board.
5. **Sidebar nav active state transitions** in < 100ms (no animation needed); the lilac background and blueberry text apply on route match (React Router 7), not on hover.
6. **Preset-chip click** triggers `POST /api/settings/providers` and optimistically inserts a new inactive `<ProviderRow />` below the active card. User must explicitly click `Set active` afterward (no auto-promote).
7. **Local transcription card is intentionally interactive but inert in Phase 5.** Per D-19, it renders with chrome but ships a "Coming in v1" matcha badge. The `small.en ✓` selected-chip styling is present so Phase 8 can light it up with one line of state change.
8. **Port input applies on next boot.** Caption under the Port row reads `Applies on next ` + `<code>yogurt start</code>` (mono inline). Acceptable to defer this caption; if added, it lives directly under the row in `--grey` 11.5px.

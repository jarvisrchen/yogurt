3. **Add the eager-load step.** After `AppState::production()` constructs the state, walk all providers via `providers::list(&db)?` and for each provider attempt `keys.get(&provider.id)` to warm any system-level caches the OS Keychain may apply. Wrap the entire bulk warm-up in `tokio::time::timeout(Duration::from_secs(5), warm_keys_task)` — on timeout, log `tracing::warn!("Keychain warm-up timed out after 5s; continuing without pre-warm")` and proceed. **Request handlers MUST still call `keys.get(provider_id)` on demand**, but the timeout ensures cold-boot is bounded.

   Add a private async helper to `state.rs`:
   ```rust
   async fn warm_keychain(state: &AppState) -> anyhow::Result<()> {
       use std::time::Duration;
       let providers = yogurt_db::providers::list(&state.db)?;
       let keys = state.keys.clone();
       let warm = tokio::task::spawn_blocking(move || {
           for p in providers { let _ = keys.get(&p.id); }
       });
       let _ = tokio::time::timeout(Duration::from_secs(5), warm).await;
       Ok(())
   }

   pub async fn production_warmed() -> anyhow::Result<Self> {
       let state = Self::production()?;
       warm_keychain(&state).await?;
       Ok(state)
   }
   ```
   The bulk `spawn_blocking` move is what guarantees `keyring` calls happen off the tokio scheduler.

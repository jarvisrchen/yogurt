<objective>
Add a microphone-permission surface that is symmetrical to the existing Screen Recording one: backend detection + request, an HTTP endpoint that exposes both permission statuses together, a polling React hook, a Welcome onboarding step card with a Grant button, and a denied-state recovery card on the Library route.

Purpose: Today microphone permission is implicit — `cpal` opens the input device, macOS shows the system prompt at that moment, and if the user denies, the mic channel goes silently empty with no UI affordance to recover. After this plan, the mic-permission story mirrors screen recording exactly: detect → onboard → recover.

Output:
- `crates/yogurt-audio/src/permission.rs` extended with mic-permission fns and a `NotDetermined` enum variant.
- `crates/yogurt-server/src/audio.rs` returning a combined permission response and exposing a `POST /api/audio/microphone/request` handler.
- `web/src/hooks/useMicrophoneStatus.ts` polling parallel.
- `web/src/components/states/MicPermissionDenied.tsx` recovery card.
- `web/src/routes/Welcome.tsx` with a third inserted step card; `web/src/routes/Library.tsx` rendering the denied state.
- One Rust unit test for the new permission fn.
- 1–3 atomic commits, each a coherent slice.
</objective>

<design_decisions>
The following decisions are baked into this plan; tasks must implement them as specified. Do not relitigate.

**DD-01 — Binding strategy:** Use the `objc2` + `objc2-av-foundation` crates (latest stable: `objc2 = "0.6"`, `objc2-av-foundation = "0.3"`; pin the latest released versions reachable via `cargo search`). Rationale: `AVCaptureDevice.authorizationStatus(for:)` / `requestAccess(for:)` are Objective-C class methods with no C shim. The Phase 2 precedent of bare `extern "C"` + `#[link(name="CoreGraphics")]` worked there only because CoreGraphics actually exports C symbols (`CGPreflightScreenCaptureAccess`). AVFoundation does not. `objc2` is the idiomatic, type-safe Rust binding maintained by the same author as the legacy `objc` crate. Adding it costs ~50KB of compile-time deps and zero runtime overhead.

**DD-02 — Enum extension over reuse:** Add `PermissionStatus::NotDetermined` as a new variant rather than collapsing `notDetermined` into `Denied`. Rationale: the two states want different UI — "click Grant" vs "open System Settings". The screen-recording path doesn't currently use NotDetermined (CGPreflightScreenCaptureAccess only returns bool), and that's fine — it simply never produces the variant. The enum stays a single shared type to keep the HTTP wire shape clean.

**DD-03 — Endpoint extension, not sibling:** Extend the existing `GET /api/audio/permission` to return `{ screen_recording: "...", microphone: "..." }` instead of adding `GET /api/audio/permissions` (plural). Rationale: the only consumer is the same-repo SPA shipped in the same binary; backward compatibility is moot. The current single-field `{ status }` shape is internal API. Renaming saves a route and avoids the singular/plural foot-gun.

**DD-04 — Separate hooks, not a combined one:** Keep `useScreenRecordingStatus` and add a parallel `useMicrophoneStatus` rather than merging into `usePermissionStatuses`. Both hooks share a single `useQuery` cache key (`["audio", "permission"]`) and `select` their slice — this gives one network poll per 2s while preserving the existing call-site shape across `useScreenRecordingStatus`'s three consumers (Welcome, Library, useFirstRunRedirect). Less churn, same network cost.

**DD-05 — Mic request endpoint is a dedicated POST:** Add `POST /api/audio/microphone/request` rather than auto-prompting at app boot. Rationale: matches the deliberate Welcome-flow gesture (user clicks a button labeled "Grant Microphone"); avoids surprising the user with a system dialog on first launch before they've seen the explanation copy. The handler is fire-and-forget — it calls `request_microphone_permission()` and returns `{status: "..."}` with the *current* (likely still NotDetermined) state, exactly like `CGRequestScreenCaptureAccess` does.

**DD-06 — Backend `start_capture()` does NOT gate on mic permission:** Phase 2's start_capture gates on screen-recording denial (`AudioError::PermissionDenied`). Do not add a parallel mic gate — `cpal::Device::build_input_stream` already fails fast if mic is denied, and adding a duplicate guard introduces a second TCC racy probe with no benefit. The UI gate (Welcome CTA disabled) is the user-facing protection; the server-side cpal failure is the safety net.

**DD-07 — No Info.plist / NSMicrophoneUsageDescription work:** Out of scope. Yogurt ships as a CLI binary, not a `.app` bundle — bundle plumbing is a separate future packaging concern. macOS WILL still prompt for mic permission from a non-bundled CLI (it uses the parent app's TCC entry, falling back to the binary's bundle id). The system dialog text will be macOS-generic ("yogurt would like to access the microphone") rather than custom — acceptable for this iteration.
</design_decisions>

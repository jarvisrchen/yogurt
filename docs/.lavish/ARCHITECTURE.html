Glossary

This page leans on a few acronyms. These three carry most of the weight.

STT Speech to text

Turning spoken audio into written words, also called ASR or "transcription". In yogurt this is the yogurt-stt crate, with two interchangeable engines behind one Stt trait: Deepgram in the cloud, or whisper.cpp on your Mac. It produces the live transcript.

LLM Large language model

The thing you send text to and get text back from (GPT, Claude, Llama, MiniMax). Used in exactly two places: turning sparse notes plus transcript into augmented notes, and answering chat questions. Never used for transcription.

VAD Voice activity detection

A cheap check for "is anyone actually talking?" that runs before the expensive model does. Only on the local STT path (vad.rs). It chops audio into utterances and skips silence, which is why local transcription costs nothing while idle.

The one contract everything depends on

yogurt-audio emits 16 kHz mono i16 PCM, 320 samples (20 ms) per Frame, on two independent channels. Both STT adapters consume exactly that. Nothing resamples at the STT boundary. Mic renders as "Me", system loopback as "Them", which is the whole of our diarization.

02

Process and thread topology

The interesting constraint: cpal::Stream is !Send, so the capture handle cannot live in a tokio task. That single fact shapes the whole recording path.

Threads, tasks, and who owns the capture handle

    end
    subgraph RT["tokio runtime"]

        STTT["STT session task<br/>(AbortOnDrop guard)"]
        PERS["persist_transcript task"]
        WSC["one task per WS client"]
        HTTP["axum request handlers"]

    CB["CoreAudio / SCK callbacks<br/>realtime, ring write only"]
    CB -->|"ring buffer"| DRAIN["drainer tasks<br/>resample, chunk, broadcast"]
    DRAIN -->|"broadcast Frame, cap 256"| SUP
    CAP -.->|"owns, RAII drop stops capture"| CB
    SUP -->|"broadcast AudioChunk"| STTT
    STTT -->|"TranscriptEvent"| PERS
    STTT -->|"TranscriptEvent"| WSC
    HTTP -.->|"start / stop"| CAP

Realtime callbacks never allocate or lock

They write into a ring buffer. A tokio drainer does the resample, quantize, chunk, and broadcast.

RAII is the stop mechanism, with one cpal caveat

Dropping AudioStream stops both cpal and the SCStream. stop() joins the thread so back-to-back starts cannot overlap SCK sessions. cpal 0.15's macOS backend keeps an Arc self-reference per stream, so a plain drop never reaches the audio unit; the Drop impls in mic.rs and echo.rs call pause() first, which is what actually silences the hardware.

Mic echo is a second consumer of the mic callback

The callback tees into an extra ring only while an echo is active. MicEcho owns a cpal output stream that drains it, fans mono out to every channel, and zero-fills while muted. If the device cannot run at the mic's rate (a Bluetooth headset at 16 kHz), a small linear resampler in the output callback bridges the gap rather than refusing the device.

The capture thread is wrapped in catch_unwind

A panic inside ScreenCaptureKit (usually a TCC denial) becomes a clean 400 with a permission hint, not a mystery "channel closed".

Broadcast, not mpsc, for frames

256 frames is about 5 seconds. A slow consumer gets Lagged(n) and drops old audio, which is correct for wall-clock-bound speech.

Why ?token= on WebSockets

The browser WebSocket API cannot set headers, and echoing a subprotocol for auth violates RFC 6455 if done sloppily. The accepted tradeoff is tokens in URLs, mitigated by redacting ?token= from tracing output.

is_final comes from speech_final

Not Deepgram's is_final. Reading the wrong field made every interim-final render as a new locked line. endpointing=1000 turns fragments into sentences.

Subscription order is load-bearing

Persistence and STT both subscribe before the audio pump publishes, so no opening words are dropped.

Backpressure is visible, not silent

64-chunk try_send buffer per channel. After 50 consecutive drops, the server emits [stt overloaded, transcript may be lossy].

Frontend reconnects with backoff

Exponential, capped at 3 attempts, with connecting / reconnecting / offline surfaced in the UI.

The black / grey UX in one paragraph

yogurt-notes parses both the user's markdown and the LLM's markdown into block ASTs, keys blocks by normalized text, and for every LLM block that is not a user block emits Source::AiGrey with a guessed transcript timestamp. Those get wrapped in <span data-ai-grey data-ts=...>, which is what TipTap styles grey and what makes click-to-transcript work. User blocks pass through verbatim, which is the invariant that makes the feature trustworthy.

Three defensive layers, because real models misbehave

Mojibake repair (CP1252-mangled punctuation, observed live from MiniMax), scaffolding strip (models echoing the prompt's XML tags), then ammonia sanitization before anything is persisted. A hallucinated <script> never reaches SQLite or disk.

Hashes are real, not copied from a manifest

Models come from the ggerganov/whisper.cpp HuggingFace repo, and every SHA256 in models::REGISTRY was verified against the actual blob (2026-06-28). A mismatch deletes the file and shows the expected/actual pair in the dialog, so a truncated or MITM'd download can never be silently used.

At meeting start, select_stt checks the .sha256 sidecar rather than rehashing a multi-GB file. The one-time legacy migration path can hash, which is why the whole check runs on spawn_blocking. WhisperLocal::load then reads the model (up to 3 GB) and runs ggml init, also on spawn_blocking.

7.2  How local decoding actually works

The cloud adapter hands audio to Deepgram and gets lines back. The local adapter has to build that behavior itself, with a VAD gate plus two different decoders against one shared model.

VAD gate, then two sampling strategies against one WhisperContext

    subgraph Shared["One WhisperContext, shared by Arc (the model weights)"]
        CTX["ggml model in RAM<br/>Metal backend"]
    end

    MICF["mic frames"] --> SEGM["Segmenter (mic)"]
    SYSF["system frames"] --> SEGS["Segmenter (system)"]

    subgraph VADBOX["VAD gate: silence is never decoded"]
        SEGM
        SEGS
    end

    SEGM -->|"full utterance"| FIN["BeamSearch decoder<br/>beam_size 5, patience 1.0<br/>set_no_context(false)"]
    SEGS -->|"full utterance"| FIN
    MICF -->|"rolling 5 s window, every 1 s"| PART["Greedy decoder<br/>best_of 1<br/>set_no_context(true)"]

    FIN -->|"is_final true, locks in dock"| OUT["TranscriptEvent"]
    PART -->|"is_final false, still listening"| OUT

    FIN -.->|"fresh WhisperState per call"| CTX
    PART -.->|"fresh WhisperState per call"| CTX

VAD first, decode second

MIN_SPEECH_MS 250 (shorter is a cough, discarded), SILENCE_HANG_MS 600 (end of utterance), MAX_SEGMENT_MS 25 s (so one monologue cannot stall the decoder). Silence costs literally nothing, which is the structural difference from the cloud path.

Mic and system get their own segmenter

Independent speakers with independent pauses. A shared segmenter would splice "Me" and "Them" into one utterance.

Two sampling strategies, one model

Greedy best_of: 1 on a rolling 5 s window every 1 s gives live partials. BeamSearch beam_size: 5 on complete utterances gives the finals. Slower and much better, which is right when one output is throwaway and the other is permanent.

set_no_context differs per decoder

Partials run no_context(true) so a hallucination cannot carry forward. Finals run no_context(false) so consecutive utterances read coherently.

Fresh WhisperState per decode

The weights (WhisperContext) are shared by Arc. create_state is cheap, and pooling would complicate the spawn_blocking lifetimes for no gain.

Metal on, CoreML off

whisper-rs is pulled in only by yogurt-stt's local-stt feature with metal enabled. coreml (ANE) is deliberately skipped: it would add a model-conversion step to the build.

The invariant not to break

whisper_full is synchronous C++ that blocks for hundreds of ms to several seconds. Every decode site in whisper_local.rs is wrapped in tokio::task::spawn_blocking: the mic final decoder, the system final decoder, and the partial ticker. Remove one and you deadlock the WebSocket broadcast pump under load. There should always be at least three occurrences in that file.

7.4  The local LLM side

Independent of local STT, and it needs no new code at all: yogurt-llm speaks OpenAI-compatible HTTP and OpenAiCompatClient takes an arbitrary base_url. Two shipped presets are already localhost.

Presetbase_urlDefault model
Ollama (local)http://localhost:11434/v1llama3.2
LM Studio (local)http://localhost:1234/v1blank, you pick in LM Studio

Pointing the active provider at either one makes enhance and chat fully local. Nothing else in the pipeline changes: the same prompts render, the same merge runs, the same sanitizer applies. The API-key field still writes to the key file, which local servers simply ignore.

The honest caveat

Local partial quality is openly worse than Deepgram's, and whisper_local.rs says so: it is "the privacy escape hatch, not the daily driver". Greedy decoding on a 5 s window cannot match a cloud model with full acoustic context, and beam-search finals arrive after the utterance ends rather than streaming through it. What you get in exchange is that nothing ever leaves the machine, and the meeting costs nothing. A real tradeoff presented as one, not a feature-parity claim.

One SQLite file, two independent openers

yogurt-server::storage and yogurt-db both resolve ~/.yogurt/db.sqlite and both run their own idempotent migrations. Keep the two path helpers in sync.

Dual pool, WAL

One writer connection behind a mutex, one read-only connection, synchronous=NORMAL.

Every DB touch goes through spawn_blocking

rusqlite is synchronous. Same for the markdown export, which does write + rename + fsync.

Markdown files are an export, not the truth

SQLite is authoritative. The .md file exists so notes are portable and greppable outside the app.

Keys

API keys are never in SQLite and never in a response body. The providers table holds base_url, model, and active flag; the secret lives in ~/.yogurt/keys.json keyed by the provider's ULID. The file is parsed once at boot into an in-memory map, so key reads are plain lookups; every write goes through a 0600 temp file and an atomic rename. Responses return a masked suffix only. The macOS Keychain was dropped on 2026-08-29: its per-binary-signature ACLs re-prompted on every dev rebuild, a wedged prompt could hang boot, and machines without Keychain write access could not run yogurt.

Localhost binding is not the boundary

Image preloads, iframes, and link-preview SSRF can reach GETs without CORS protection, which is why even device enumeration requires the token. Unauthenticated settings writes were a real finding: before hardening, any localhost-reaching page could POST /api/settings/providers and repoint the active LLM at an attacker base_url.

Free fallbacks

If no provider is configured at all, MockLlm answers deterministically at $0. A provider that is configured but whose stored key cannot be read is a hard 502, never a silent free fallback, so you can never be quietly downgraded to fake output.

STT is where the money goes, and it bills at 2×

The mic and system channels are two separate Deepgram WebSocket sessions (spawn_supervised_session is called once for Channel::Mic, once for Channel::System). Both stream continuously for the whole meeting, including silence, because the cloud path has no VAD gate.

The headline number

Billed minutes = 2 × wall-clock meeting length, regardless of how much anyone actually talks. A solo meeting where nobody else is on the call still pays for the system channel streaming an hour of silence.

Roughly $0.60 to $0.90 per meeting-hour. A 20 h/month meeting habit is about $12 to $18/month.

The local path is structurally different

vad.rs only hands whisper.cpp segments where speech was actually detected (MIN_SPEECH_MS 250, SILENCE_HANG_MS 600, MAX_SEGMENT_MS 25 s), so silence costs nothing at all. Local mic and system each get their own segmenter, and every decode runs on spawn_blocking.

The LLM calls are cheap, but one of them grows

Enhance, for a 1-hour meeting, sends roughly:

Part of the promptApprox tokens
enhance.md instructions (fixed, 2.6 KB)~650
User's sparse notes100 to 400
transcript_json~24,000
Output (the merged document)400 to 1,200

The transcript is the whole cost. It goes to the model as raw JSON, not prose, so every segment carries {"ts_ms":3600000,"channel":"them","text":"..."} scaffolding. At ~700 utterances per hour that JSON punctuation alone is roughly 14k tokens on top of ~10k tokens of actual words. The model needs ts_ms to emit the data-ts timestamps that make click-to-transcript work, so this is a real tradeoff, not waste, but it is where the tokens are.

Chat is the line item to watch

Every message re-sends the entire transcript plus the entire prior conversation:

cost(message N) = system prompt + FULL transcript so far + all N-1 prior messages

There is no windowing, no truncation, and no summarization anywhere in run_stream. Ten questions across a one-hour meeting is on the order of 120k input tokens, about $0.02 on MiniMax, which is fine. But the growth is quadratic in messages-times-meeting-length, so a long meeting with heavy chat use is the one path that can surprise you.

Switch STT to local and the same meeting costs ~$0.025. Switch STT and the LLM to local (whisper.cpp + Ollama) and it costs $0.00, paid instead in battery, fan noise, and a one-time model download.

The one-time cost of local mode is disk and bandwidth for the model (75 MB to 3.1 GB), plus battery and thermals while decoding. See 7.3 Choosing a model for sizes and 7.2 for why silence is free there.

What the architecture does and does not do about cost

present Local-everything escape hatch

Both AI surfaces sit behind traits (Stt, LlmClient), so $0 mode is a settings change, not a fork.

present Hard timeout on enhance

LLM_HTTP_TIMEOUT means a hung provider cannot bill indefinitely.

present Visible STT backpressure

Surfaces [stt overloaded, transcript may be lossy] rather than silently paying for audio it dropped.

present Env-overridable Deepgram model

YOGURT_DEEPGRAM_MODEL trades quality for price without a rebuild.

Not present, in rough priority order if cost ever matters:

#GapWhy it matters
1 No gating of the system channel It streams silence for the entire meeting at full price. Gating on output-audio activity would cut the Deepgram bill by close to half for solo work.
2 No transcript windowing in chat Every message pays for the full transcript again.
3 No prompt caching The enhance.md prefix is fixed at ~650 tokens and the chat system prompt is stable, but neither claims providers' cached-input discounts (OpenAI prices cached input at half rate).
4 No spend meter Nothing tells the user what a meeting cost, which for a BYO-key product is the number they would most want to see.
5 Re-enhance is a full re-run Full price each time, no diffing against the previous result.

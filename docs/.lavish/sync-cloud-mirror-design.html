Yogurt Cloud: push meetings to your own Supabase, read them on your phone

Yogurt stays a local app with no login. Yogurt Cloud is an optional, encrypted mirror in a Supabase project you own. Laptops push into it and never read from it. The phone reads it after you type your passphrase. Source of truth: docs/.planning/sync-cloud-mirror-design.md.

No login to use yogurtSync stays off until you turn it on in Settings.
You host itYour Supabase project. Yogurt hosts no data.
One-wayLaptops push. The phone only reads.
Ciphertext onlySupabase never sees a title, note, or transcript.
Laptops can't decryptThey hold the public key only. A work laptop can't read your other laptops.
Every push is keptThe cloud is an append-only history. View the library as of any earlier push.

Architecture

Every arrow into Supabase carries ciphertext or credentials. GitHub Pages serves code only and never sees your project details, because they ride in the link's #fragment.

Flows

The four sequences, in the order you would live them.

History

Each push stores only what changed, plus a deletion marker for anything the device no longer has. The library as of push N is the latest version of each meeting at or before N.

Why not a snapshot per push

Same result, far more storage. Hourly auto-push of a 630 KB library is about 15 MB a day, which fills the free tier's 500 MB in about a month. Versions cost about 19 KB per change, so 500 MB holds about 26,000.

Reverting is read-only

Pick a push in the viewer to see the library as it was. Nothing flows back to a laptop. A wiped db.sqlite marks that device's meetings deleted on the next push, and they stay readable from any earlier push.

Insert-only policies

No laptop or browser can update or delete a row, so a compromised laptop can add junk but can't erase history. Purging for real happens in the Supabase SQL editor.

Stream the enhanced summary into the editor

End meeting and Re-enhance should paint text as the model produces it instead of showing a banner over a blank page. Markdown source of truth: docs/.planning/enhance-streaming-design.md. Every claim about current behavior below was checked against the code on 2026-08-29.

What changes for the user

today

Banner, then everything at once

  • End meeting awaits the whole LLM call on the in-meeting screen, then navigates. 10 to 40 s of a spinner for a real meeting.
  • Re-enhance keeps the stale summary on screen under the lilac banner until the new one lands.
  • The streaming phase in enhance_progress is emitted exactly once, after the full text has arrived. It is a Phase 4 placeholder that never streamed anything.
proposed

Text within a second, settles when done

  • End meeting navigates to the post view immediately; the post view fires the enhance call.
  • The Enhanced tab fills top-to-bottom in grey with a caret at the growing edge. Banner stays, its character count is live.
  • On done, the merged document replaces the preview in place: the user's own lines turn black and ↳ MM:SS links appear. Text does not move.
  • Editor is read-only during the stream. Errors keep today's strawberry banner + Retry.

Approaches

recommended

A · Raw preview, settle on done

Server streams the accumulated raw markdown. Browser renders it all-grey. The existing merge + sanitize runs once on the full text and the POST response swaps in the final document.

  • Reuses LlmClient::stream() and the chat loop shape verbatim.
  • Merge, sanitizer, persistence, response shape untouched.
  • The settle step is a legible "your notes were preserved" cue.
  • Preview shows no black/grey split or transcript links until the end.
upgrade path

B · Incremental merge per tick

Server re-runs mojibake fix + merge + render + sanitize on the partial text every ~80 ms and streams wire-format snapshots, so the preview already has black/grey and links.

  • No settle step; best-looking preview.
  • strip_model_reasoning / strip_prompt_scaffolding expect complete documents and can misfire on a half-written tag.
  • Trailing partial block gets a bogus timestamp guess on every tick.
  • Merge runs 100+ times per enhance instead of once. Cheap, but complexity moves into the hot loop for a cosmetic gain.
  • Same frame shape as A; only what text contains changes.
rejected

C · Fake typing of the final text

Keep the non-streaming call and animate the finished text in.

  • Time to first paint is unchanged, which is the actual complaint.

Wire contract

One frame type, backward compatible. The streaming frame gains text.

{ "type": "enhance_progress", "phase": "streaming", "chars": 1234, "text": "# Standup\n\n- ..." }

Snapshots, not deltas. events_tx is a tokio::sync::broadcast with no replay. A subscriber that connects late (the post view mounting right after End meeting) or reconnects after a drop would miss deltas and render a corrupted document. With snapshots every frame is self-contained, the client has no accumulator, and the worst case after a hiccup is one stale tick. A 5 KB document at ~12 fps over localhost is ~60 KB/s for the duration of the stream.

Changes by file

crates/yogurt-server/src/enhance.rs
Replace step 4's llm.complete() with the chat-style loop from api/chat.rs::run_stream: open inside timeout(LLM_HTTP_TIMEOUT, llm.stream(req)), consume with timeout(LLM_HTTP_TIMEOUT, stream.next()) per chunk (idle cap, not wall-clock cap), accumulate, emit a snapshot on the first non-empty delta then at most every 80 ms, plus a final one if the last delta is newer than the last emit. Chunk error → phase: "error" + 502. Delete the placeholder streaming { chars } emit. Steps 6+ unchanged.
crates/yogurt-server/tests/enhance_endpoint.rs
Assert the WS sees sending, ≥ 1 streaming frame whose text equals the mock content, then done. Persisted enriched_md expectations unchanged. MockLlm::stream() (single delta) is sufficient.
web/src/lib/ws.ts
EnhanceProgressEvent.text?: string. useEnhanceProgress exposes text: string | null, set on streaming, cleared on sending / done / error.
web/src/routes/MeetingPost.tsx
streaming = ws.phase === "streaming" && ws.text != null. While streaming: force the Enhanced tab on the first frame, pass enrichedMarkdown={ws.text} and editable={false}, set data-streaming on the wrapper. Accept location.state.autoEnhance and fire postEnhance once on mount (mirrors the existing autoStart pattern). too_short now comes from that response. On a done frame with no local POST in flight (reload mid-stream), refetch through the generation-guarded GET.

Autosave safety: YogurtEditor applies enrichedMarkdown via setContent(html, false), which never fires onChange, so enrichedEditedRef cannot flip during streaming and preview text is never persisted from the browser.

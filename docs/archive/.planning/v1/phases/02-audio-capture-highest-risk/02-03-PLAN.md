**Step 3 — write `crates/yogurt-server/src/audio.rs`** per plan lines 1920–1998:

```rust
use axum::{http::StatusCode, response::{IntoResponse, Json}};
use serde::Serialize;
use yogurt_audio::{
    has_screen_recording_permission, list_input_devices, start_capture, AudioError, AudioStream,
    DeviceInfo, PermissionStatus,
};

#[derive(Serialize)]
struct PermissionResponse {
    status: PermissionStatus,
}

/// `GET /api/audio/permission` — Screen Recording permission state. Phase 7 onboarding polls this.
pub async fn get_permission() -> Json<PermissionResponse> {
    Json(PermissionResponse { status: has_screen_recording_permission() })
}

/// `GET /api/audio/devices` — input devices for the §5.6 settings dropdown.
pub async fn get_devices() -> Result<Json<Vec<DeviceInfo>>, (StatusCode, String)> {
    list_input_devices()
        .map(Json)
        .map_err(|e| (StatusCode::INTERNAL_SERVER_ERROR, e.to_string()))
}

/// Begin recording. Phase 3 will wire this into `POST /api/meetings/:id/start`.
/// Surfaces `AudioError::PermissionDenied` for the §5.11 recovery flow.
pub fn start_meeting_recording() -> Result<AudioStream, AudioError> {
    start_capture()
}

pub struct AudioErrorWrap(pub AudioError);

impl From<AudioError> for AudioErrorWrap {
    fn from(e: AudioError) -> Self { Self(e) }
}

impl IntoResponse for AudioErrorWrap {
    fn into_response(self) -> axum::response::Response {
        let (status, body) = match self.0 {
            AudioError::PermissionDenied => (
                StatusCode::FORBIDDEN,
                serde_json::json!({
                    "error": "permission_denied",
                    "message": "macOS Screen Recording permission is required",
                    "recovery": "open System Settings → Privacy & Security → Screen Recording",
                }),
            ),
            AudioError::UnsupportedPlatform => (
                StatusCode::NOT_IMPLEMENTED,
                serde_json::json!({
                    "error": "unsupported_platform",
                    "message": "system audio capture requires macOS 13+",
                }),
            ),
            other => (
                StatusCode::INTERNAL_SERVER_ERROR,
                serde_json::json!({ "error": "audio", "message": other.to_string() }),
            ),
        };
        (status, Json(body)).into_response()
    }
}
```

[ ] Left channel (mic) is audible and contains your voice — NOT silence.
[ ] Right channel (system) is audible and contains the music/audio you played — NOT silence.
[ ] No channel swap — your voice is on the LEFT, music is on the RIGHT (not the other way around). This validates the `Channel::Mic` / `Channel::System` tag wiring.

[ ] No more than ~1 second of contiguous silence on either channel during the middle 28 seconds.
[ ] Both channels sound roughly time-aligned — when you spoke a word, the music continued underneath without obvious jumps or pauses.

- Channel swap → bug in src/lib.rs `start_capture()` (mic_tx wired to System channel or vice versa) OR in wav_eartest.rs (left/right interleaving inverted).

- Silence on system → SCK delegate didn't fire OR excludes_current_process_audio caught the wrong audio source OR Spotify wasn't actually playing.
- Clipping → resampler amplitude is over 1.0 before clamping; check Downmix::push f32→i16 conversion.
- Time misalignment → mic and system Instant::now() baselines drifted at start_capture spawn time; check D-21 from CONTEXT.md.

Resume signal: type "approved" to proceed, or describe the issue (which checkbox failed and what you heard) so it can be diagnosed and the capture re-run.

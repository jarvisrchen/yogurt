# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

> **Phase 2 is backend-heavy.** The `yogurt-audio` crate, ScreenCaptureKit integration, broadcast channels, and REST endpoints (`GET /api/audio/devices`, `GET /api/audio/permission`) are the deliverables. There is no significant frontend work in this phase — the components that consume this phase's API surface are owned elsewhere:
>
> - **Recording badge component** — owned by Phase 1 (DESIGN-05).
> - **Permission-denied recovery screen visual** — owned by Phase 7 (STATE-02, surfaces PRD §5.11).
> - **First-time onboarding screen-recording prompt visual** — owned by Phase 7 (STATE-04, surfaces PRD §5.10).
> - **Settings "Input device" dropdown** — owned by Phase 5.
>
> Phase 2 only contributes the **typed error surface** (`AudioError::PermissionDenied`) and the **user-facing copy** that Phase 7 will render. The OS-supplied TCC prompt itself is not styled by us. The 30-second ear-test acceptance gate produces a WAV file artifact, not a UI surface.
>
> This UI-SPEC therefore **inherits aggressively from Phase 1** and introduces no new tokens.

## Copywriting Contract

These are the user-facing strings **introduced by Phase 2**. Phase 7 renders them inside the styled permission card (STATE-02 / STATE-04). Phase 2 owns the copy; Phase 7 owns the visual treatment.

| Element | Copy |
|---------|------|
| Primary CTA | Grant Screen Recording permission |
| Empty state heading | (none — Phase 2 has no empty state UI) |
| Empty state body | (none) |
| Error state | macOS needs Screen Recording permission to capture system audio. |
| Destructive confirmation | (none in Phase 2) |

### Supporting copy (paired with the error state)

| Element | Copy | Notes |
|---------|------|-------|
| Error secondary action | Open System Settings | Button rendered alongside the error state. Triggers `x-apple.systempreferences:com.apple.preference.security?Privacy_ScreenCapture` (Phase 7 wires the URL handler). |
| Restart-required footer | Restart once after granting — a macOS quirk, not us. | Required by PRD §5.10. Surfaces the TCC limitation captured in D-24: `CGPreflightScreenCaptureAccess` returns cached state, so the binary must restart before the new grant takes effect. |
| Error context line (optional) | Yogurt captures system audio without joining the call as a bot. | Brand reinforcement; Phase 7 may show or omit at its discretion. |

### Copy guardrails

- Never blame the user. "macOS needs ..." frames the OS as the gatekeeper.
- Never use "Allow" or "Enable" alone as a button label — they're context-free. Always pair the verb with the object ("Grant Screen Recording permission", "Open System Settings").
- Never use destructive language ("failed", "denied", "blocked") in the user-facing copy. The typed enum is `AudioError::PermissionDenied` for engineers; the user sees "macOS needs Screen Recording permission ...".
- The "Restart once after granting" footer is **load-bearing UX**, not optional polish — without it, users grant permission, see no change, and assume the app is broken.

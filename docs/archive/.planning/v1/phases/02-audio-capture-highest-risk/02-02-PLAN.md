<objective>
Implement microphone and system-audio capture pipelines that both emit `Frame`s into Tokio broadcast channels, then expose the public `start_capture()` orchestrator that downstream STT consumers (Phase 3) will call.

Purpose: This plan turns the contract scaffolded in Plan 01 into a working two-stream audio pipeline. Microphone capture via `cpal` resamples the default input device (typically 48 kHz f32) down to 16 kHz mono i16 inside the capture callback. System audio capture uses either in-process ScreenCaptureKit (Path A, the preferred path) or a Swift sidecar binary (Path B, fallback) depending on the spike outcome committed in Plan 01. Both producers feed `tokio::sync::broadcast` channels with capacity 256 frames each. The `start_capture()` public function returns an `AudioStream` that owns both producers — dropping it stops both streams via RAII (AUDIO-06's "supervisor terminates cleanly" plumbing).

Output:
- `crates/yogurt-audio/src/resample.rs` — shared `Downmix` helper (rubato-based).
- `crates/yogurt-audio/src/mic.rs` — `cpal` mic capture, `FrameChunker`, `DeviceInfo`, `list_input_devices()`, `spawn_mic_capture()`.
- `crates/yogurt-audio/src/system.rs` — SCK or sidecar system audio capture, `spawn_system_capture()`, `SystemCapture`.
- `crates/yogurt-audio/src/lib.rs` — `AudioStream` + `start_capture()` orchestrator.
- Manual-smoke examples (`mic_smoke`, `system_smoke`, `dual_smoke`) for human verification.
- (Path B only) `tools/yogurt-audio-helper/` Swift binary.

AUDIO-02 (mic 16 kHz mono i16), AUDIO-03 (system audio with `excludes_current_process_audio=true`), AUDIO-04 (broadcast capacity ≥ 256), AUDIO-05 (meeting-relative clock from `Instant::now()`) all satisfied.
</objective>

```rust
use tokio::sync::broadcast;

/// Live capture handle. Drop to stop both streams.
#[derive(Debug)]
pub struct AudioStream {
    _mic: MicCapture,
    _system: SystemCapture,
    pub mic_tx: broadcast::Sender<Frame>,
    pub system_tx: broadcast::Sender<Frame>,
}

impl AudioStream {
    pub fn subscribe_mic(&self) -> broadcast::Receiver<Frame> { self.mic_tx.subscribe() }
    pub fn subscribe_system(&self) -> broadcast::Receiver<Frame> { self.system_tx.subscribe() }
}

pub fn start_capture() -> Result<AudioStream> {
    // Permission gate BEFORE opening the mic — user shouldn't hear a recording indicator
    // if system capture is going to fail.
    if has_screen_recording_permission() == PermissionStatus::Denied {
        return Err(AudioError::PermissionDenied);
    }

    let (mic_tx, _) = broadcast::channel::<Frame>(256);
    let (system_tx, _) = broadcast::channel::<Frame>(256);

    let _mic = spawn_mic_capture(mic_tx.clone())?;
    let _system = spawn_system_capture(system_tx.clone())?;

    Ok(AudioStream { _mic, _system, mic_tx, system_tx })
}
```

Both channels MUST have capacity exactly 256 (AUDIO-04 requirement: ≥ 256 frames). Both `Instant::now()` baselines are seeded synchronously inside `start_capture()` (already done inside each `FrameChunker::new()`) — meeting-relative clock per AUDIO-05.

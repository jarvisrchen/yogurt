# Phase 9 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

> **Phase 9 introduces NO new graphical UI.** This phase ships the release pipeline (GitHub Actions, Homebrew tap, notarization, `cargo publish`), README content, and the `yogurt doctor` CLI subcommand. All in-app surfaces are inherited unchanged from Phases 1–8. The only "UI" Phase 9 contributes is **terminal output styling and CLI help-text copy**. This spec exists because the UI-gate inventory lists Phase 9 as having UI; in practice it is a copywriting contract for the CLI.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | terminal default fg | All body diagnostic text |
| Secondary (30%) | terminal default fg | Section headings (bold, no color) |
| Accent (10%) | ANSI 32 (green) | `✓` success markers only |
| Destructive | ANSI 31 (red) | `✗` failure markers only |
| Warning | ANSI 33 (yellow) | `⚠` warning markers only |

Inherited from web UI. CLI output uses terminal default colors with sparing ANSI accents for status only (green `✓` OK, red `✗` fail, yellow `⚠` warning). Verify exact escape codes against superpowers plan Tasks 9.7–9.10 (yogurt doctor implementation). Color must degrade gracefully when stdout is not a TTY (`--json` mode emits zero ANSI codes).

Accent reserved for: status glyphs only — never for body text, never for headings, never for "press here" affordances (CLI has no affordances).

## Copywriting Contract

Phase 9's actual contribution is **CLI copy**. The strings below are the contract; implementation in `crates/yogurt-cli/src/commands/doctor.rs` must match.

| Element | Copy |
|---------|------|
| Primary CTA | (none — Phase 9 has no in-app primary CTAs) |
| Secondary CTA | (none in-app — only README install instructions: `brew install jarvisrchen/yogurt/yogurt && yogurt start`) |
| Empty state heading | (none in-app — `yogurt doctor` runs a fixed diagnostic flow with no empty state) |
| Empty state body | (none in-app) |
| Error state (CLI) | See "Diagnostic Error States" table below |
| Success state (CLI) | `✓ All systems go. yogurt start to begin.` |
| Destructive confirmation (CLI) | `About to delete ~/.yogurt/models/ (this removes downloaded whisper.cpp models). Type 'yes' to confirm:` |

### Diagnostic Error States (`yogurt doctor`)

Each diagnostic check emits one line matching this pattern: `{glyph} {problem} — {remediation}`. The remediation MUST be a copy-pasteable command.

| Condition | Output |
|-----------|--------|
| Screen Recording not granted | `✗ Screen Recording permission not granted — run: yogurt doctor --reset-screen-recording` |
| Port 7878 in use | `✗ Port 7878 in use by PID {pid} ({process_name}) — kill it or run: yogurt start --port 8989` |
| Local whisper.cpp model missing | `⚠ Local model not found — run: yogurt doctor --redownload-model small.en` |
| All checks pass | `✓ All systems go. yogurt start to begin.` |

### README Install Snippet (canonical)

The README install section must show all three install channels and clearly mark the recommended path for non-developers:

```
# Recommended (non-developers):
brew install jarvisrchen/yogurt/yogurt && yogurt start

# Rust developers:
cargo install yogurt && yogurt start

# Direct download:
# https://github.com/jarvisrchen/yogurt/releases/latest
```

The Homebrew one-liner `brew install jarvisrchen/yogurt/yogurt && yogurt start` is canonical and must appear verbatim — it's referenced from the PRD §11, ROADMAP Phase 9 success criteria, and the DIST-09 human-verify gate.

### `--json` Output Constraints

`yogurt doctor --json` emits machine-readable diagnostics for bug reports. The JSON output MUST:
- Contain zero ANSI escape codes.
- Report provider **names** only — never API key values.
- Report note presence as a count — never note content.
- Use boolean `ok` + string `remediation` fields per check, mirroring the human-readable lines above.

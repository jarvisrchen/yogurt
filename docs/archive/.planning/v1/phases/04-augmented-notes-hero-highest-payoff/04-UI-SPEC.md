# Phase 4 — UI Design Contract

> Visual and interaction contract for the **Augmented Notes Hero** — the entire core value of Yogurt. The black-user / grey-AI in-place augmented-notes merge IS the product; every motion token, every hex code, and every copy string in this spec is load-bearing. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Copywriting Contract

This is the hero — copy matters. The "Weaving your notes into the transcript…" string is canonical and must appear verbatim.

| Element | Copy |
|---------|------|
| Primary CTA (in-meeting) | **`End meeting`** — triggers the enhance pipeline (POST `/api/meetings/:id/enhance`) and navigates to `/meeting/:id/post`. |
| Secondary CTA (post-meeting, top-right) | **`Re-enhance`** — re-runs the same bundled `enhance.md` prompt against current notes + transcript. While in flight, label becomes `Re-enhancing…`. No dropdown caret. No template picker. |
| Editor empty state heading (TipTap placeholder) | **`Type notes here…`** |
| Editor empty state body | **`Bullets you write stay black. AI fills in grey after you end the meeting.`** |
| Enhancing state banner copy | **`Weaving your notes into the transcript…`** (verbatim, 13px Hanken 600, on lilac `var(--blsoft)` surface, with pulsing `var(--blue)` dot left of copy and JetBrains-Mono character-streaming count right of copy when `chars` is present, e.g. `1,234 chars`) |
| Re-enhance in-flight label | **`Re-enhancing…`** |
| Error state | **`Couldn't enhance — your notes are saved. Try Re-enhance, or check Settings → Model.`** (preserves user content; user notes are NEVER lost. Settings link is a soft pointer to Phase 5 even though Phase 4 doesn't ship that UI.) |
| Destructive confirmation | **(none)** — editing a grey range simply promotes it to black; the `aiGrey` mark is stripped from edited characters only. The change is "reversible" only via Re-enhance, which is itself non-destructive. No modal, no toast, no confirm. |
| Legend label (user swatch) | **`your notes`** (next to a 12×12 ink-black square) |
| Legend label (AI swatch) | **`AI`** (next to a 12×12 grey square) |
| Deep-link content (rendered) | **`↳ HH:MM`** — e.g. `↳ 11:02`. The down-right arrow glyph (`↳`, U+21B3) followed by a space and a zero-padded `HH:MM` from JetBrains Mono. |
| Deep-link hover tooltip | The transcript-segment excerpt at that timestamp, populated via native `title` attribute on render. |

## Registry Safety

**No third-party UI registries used.** No shadcn blocks. The hero UI is built from custom TipTap marks + custom inline atom nodes + plain React components.

| Registry | Blocks Used | Safety Gate |
|----------|-------------|-------------|
| shadcn official | none | not required |
| third-party (any) | none | not required |
| **TipTap 3.x** | `@tiptap/starter-kit` baseline (headings L1–L3) + custom `aiGrey` mark + custom `transcriptLink` inline atom node | First-party (Tiptap official); no third-party extensions. `prosemirror-markdown` (official ProseMirror package) handles round-trip serialization with custom serializer/parser tokens for the `aiGrey` mark + `transcriptLink` node (per D-05). `@tiptap/extension-markdown` was explicitly **rejected** — the custom-plugin path is mandatory either way, and `prosemirror-markdown` exposes first-class hooks. |

**Custom TipTap surfaces introduced this phase (authoritative list):**

| Surface | Kind | Attributes | HTML wire format |
|---------|------|------------|-------------------|
| `aiGrey` | Mark | `transcriptTs: number \| undefined` | `<span data-ai-grey data-ts="N" class="ai-grey">…</span>` |
| `transcriptLink` | Inline atom node (`group: "inline"`, `inline: true`, `atom: true`, `selectable: false`) | `ts: number` | `<span data-transcript-link data-ts="N" class="transcript-link">↳ HH:MM</span>` |

`transcriptLink` is a node (not a mark) so users cannot split it mid-word; `aiGrey` is a mark so promote-on-edit can strip it from a single character span without affecting surrounding grey.

## Motion Contract (Load-Bearing — PRD §16.4 / §16.5)

These values are NOT design tokens to be tuned later. They are part of the hero's felt-quality bar. Acceptance verification requires DevTools Animations panel to report these exact durations.

| Animation | Duration | Easing | Where |
|-----------|----------|--------|-------|
| **Shimmer skeleton** | **1.25s** | `linear infinite` | Every `<ShimmerSkeleton>` rendered while enhancing. Keyframes: `background-position: 200% 0 → -200% 0`. Gradient `#EFE6D6 → #F8F1E0 → #EFE6D6`, `background-size: 200% 100%`. |
| **Active-dot recpulse** | **1.4s** | `ease-in-out infinite` | Pulsing `var(--blue)` dot left of "Weaving your notes…" banner copy. Same keyframes as the Phase 3 recording dot. |
| **Enhancing progress bar** | 1.8s | `ease-in-out infinite` | Indeterminate sweep across the `#D9D4F4` track inside the lilac banner, fill `var(--blue)`, 30% width. Keyframe name `enhancing-bar`. |
| **Skeleton-to-text stagger** | **140ms / 340ms / 560ms / 760ms** | per-item ease | Exact `staggerMs` props passed to the four `<ShimmerSkeleton>` instances on `MeetingPost` mount. Hardcoded — do not round, do not interpolate, do not parameterize. PRD §16.5. |
| Slide-in (transcript dock, consumed) | 340ms | `cubic-bezier(.2,.7,.2,1)` | Set by Phase 3; Phase 4's deep-link click triggers it when the dock is collapsed. |

## Interaction Contract (Hero Behaviors)

### Promote-on-edit (the felt-quality test)
When the user types inside an `aiGrey` range, the typed character renders ink-black instantly — surrounding grey is untouched. Implemented via an `appendTransaction` ProseMirror plugin registered on the `aiGrey` mark (D-04). Black ranges are NEVER overwritten on Re-enhance.

### Deep-link click
Clicking a `↳ HH:MM` token: (a) opens the Phase 3 transcript dock if collapsed, (b) dispatches `window.dispatchEvent(new CustomEvent("yogurt:transcript:scrollTo", { detail: { ts } }))` which the Phase 3 `TranscriptPanel` listens for. Handler is event-delegated on `editor.view.dom`. Hover surfaces the segment excerpt via native `title` attribute.

### Re-enhance click
Single button, top-right. POSTs `/api/meetings/:id/enhance`, sets `enhancing=true` until the WS `done` event fires (or the fetch resolves), then `editor.commands.setContent(renderToHtml(enriched_md))`. Promoted-black ranges from the previous round survive verbatim (per D-08 block-key merge).

### Enhancing-state UI sequence
1. `MeetingPost` mounts → `EnhancingBanner` is sticky-visible at top (lilac, with pulsing dot + "Weaving your notes into the transcript…" + progress bar + character count).
2. Four `<ShimmerSkeleton>` placeholders animate at 1.25s linear infinite in the editor column.
3. At 140ms, 340ms, 560ms, 760ms post-mount, each skeleton resolves into a grey markdown bullet.
4. On WS `enhance_progress` `done` (or fetch resolution), the banner is removed and the full merged document is set into the TipTap editor.
5. Re-enhance button returns to idle (`Re-enhance`).

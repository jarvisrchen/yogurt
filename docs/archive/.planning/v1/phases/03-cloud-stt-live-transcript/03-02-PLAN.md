<objective>
Wire the audio broadcast (Phase 2) to the STT trait (Plan 01) inside an in-memory `meetings::Registry`, expose the lifecycle as three REST endpoints, and serve transcript events to browsers via a new `/ws/meetings/:id` WebSocket route.

Purpose: This is the server-side fan-out story. After this plan lands, anyone holding a `MeetingId` can `POST /api/meetings/:id/start` to begin a session, open a WS to `/ws/meetings/:id`, and receive `{"type":"transcript","payload":{...}}` frames in real time. Phase 7 will swap the in-memory `HashMap` for SQLite behind the same `Registry` API.

Output: `Registry`, `Meeting`, `AppState`, three REST routes, one WS route, three integration tests (REST lifecycle, WS fan-out, < 200ms latency).
</objective>

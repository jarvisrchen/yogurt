<objective>
Wire `POST /api/meetings/{id}/enhance` to the user's configured LLM provider. Today step 4 of the handler only checks `YOGURT_LLM_*` env vars via `llm_openai::from_env()`; nothing sets those, so every enhance silently uses `MockLlm` even when an active Minimax provider with a Keychain key is configured in Settings.

Purpose: enhance is the hero feature; it must use the LLM the user configured.
Output: a small resolution helper (`from_active_provider`) in `llm_openai.rs`, the enhance handler rewired to the env -> provider -> mock priority chain, and unit tests covering all three provider-resolution branches.

Diagnosis is done and verified live - do not re-investigate. All building blocks exist:
- `yogurt_db::providers::active(&db) -> Result<Option<Provider>>` (crates/yogurt-db/src/providers.rs:124) returns the single active LLM provider (`Provider { id, name, base_url, model, is_active, created_at }`).
- `state.keys: Arc<dyn ApiKeyStore>` with `fn get(&self, account: &str) -> Result<Option<String>>` (crates/yogurt-db/src/keychain.rs:27-28); key account = provider id. `KeychainStore` in prod, `MemoryKeyStore` in tests.
- `yogurt_llm::OpenAiCompatClient::new(base_url: String, api_key: String, model: String)` (crates/yogurt-llm/src/lib.rs:84), re-exported from `crate::llm_openai`. Accessors `base_url_for_streaming()` / `model_for_streaming()` / `api_key_for_streaming()` exist for test assertions.
- SET-10 rule (state.rs module docs): handlers MUST NOT call `keys.get()` on the tokio reactor - wrap in `tokio::task::spawn_blocking`.

Chat handler and `AppState.llm` are explicitly OUT of scope (Phase 6 owns its provider lookup).
</objective>

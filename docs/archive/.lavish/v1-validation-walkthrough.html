step 1

One-time setup

./scripts/setup.sh — runs once

One script handles everything: checks prereqs (macOS / Rust / Node / pnpm), installs the just task runner via Homebrew so you have just release / just dev later, writes a .env.local stub for API keys, installs web dependencies, builds the web bundle, and builds the release binary.

# from the repo root — only command you have to type-from-path
./scripts/setup.sh

# expected timeline:
#   [1/5] Checking prerequisites                — instant
#   [2/5] Ensuring just task runner installed   — ~10 s if missing, instant if present
#   [3/5] Provisioning .env.local               — instant
#   [4/5] Installing web deps + build           — ~1 min
#   [5/5] Building release binary               — 8-15 min on first run

# tail looks like:
  ✓ binary built → target/release/yogurt
Done.
Next: just release   (single binary at http://localhost:7878)
      just dev       (UI dev with HMR, one terminal)
      just           (no args — lists every recipe)
Why just gets installed for you? So Step 2 onward is literally just release from anywhere in the repo — no script paths to remember. If you prefer to skip it: ./scripts/setup.sh --no-just; the ./scripts/run-*.sh entry points all still work directly.
What got written for you: .env.local in the repo root (chmod 600), with three empty lines: YOGURT_DEEPGRAM_API_KEY, YOGURT_OPENAI_API_KEY, and commented-out alternatives for Minimax / OpenRouter. The setup script doesn't fail if you leave them blank — but transcription needs Deepgram and augmented notes need an LLM key, so fill at least those two before step 3.

1a · Paste your API keys required

Open .env.local (the IDE already has it open). You need:

  • Deepgram for cloud transcript. Sign up at console.deepgram.com — they hand out $200 free credit.
  • One LLM key (OpenAI is simplest). Phase 4 augmented notes + Phase 6 chat both consume it.

The keys get loaded into .env.local → seeded into SQLite + macOS Keychain on first launch with --dev. Release-installed binaries from brew never touch that file (privacy invariant SET-11).

Don't have Xcode CLI tools? xcode-select --install first — whisper-rs-sys needs the C toolchain. If ./scripts/setup.sh errors at step 4 with linker `cc` not found, that's why.
Plan for ~12 GB of free disk. Release build → 4–6 GB of target/ + 2–4 GB of cargo registry + ~500 MB of node_modules. Setup script warns if you have less than 8 GB.

1b · Recovery — if setup fails if needed

The script stops on the first failure and tells you what to do. Common ones:

  • "cargo not found" → install Rust at https://rustup.rs, then re-run.
  • "pnpm not found" → brew install pnpm, then re-run.
  • "no space left on device" → free 2–3 GB and re-run. just clean-incremental recovers ~3 GB without wiping the whole build.
  • Stalled at step 4 for >30 min → tail the output; if you see Compiling whisper-rs-sys over and over, your machine is paging. Close Chrome.
step 2

Start yogurt

pick the right script for what you're doing

For this validation walkthrough, use just release — it boots the release binary as a single process with the web bundle baked in. Same code path a brew-installed user gets, which is the version we want to confirm works.

The dev-mode recipe (just dev) exists for editing the React UI with hot reload, but it adds a Vite process and proxy hop you don't need for acceptance testing. Covered briefly below for completeness.

2a · Release mode validation path

# single process, embedded web bundle, http://localhost:7878
just release

# expected output (~1 s for first response):
Starting yogurt (release mode) at http://localhost:7878
  Single binary with embedded web bundle — no Vite, no .env.local.
  Enter API keys via the Settings UI on first run.
  Ctrl-C to stop.

2026-06-27T... INFO yogurt::commands::start: yogurt is starting url=http://127.0.0.1:7878
2026-06-27T... INFO yogurt_db::keychain: Registered apple-native-keyring-store as default credential backend
2026-06-27T... INFO yogurt_server: yogurt-server starting addr=127.0.0.1:7878 mode=Release
Release mode doesn't read .env.local — that's a privacy invariant (SET-11). Your seeded keys won't pre-populate; you'll paste them via the Settings UI on first run. Two API keys to have ready: Deepgram (for transcript) and one LLM key (for augmented notes / chat).

2b · Port already in use interactive

If port 7878 is busy, every runner prompts you before the binary starts:

! port 7878 (release) is busy — held by PID 12345
   process: /Applications/Some.app/Contents/MacOS/some-other-thing

   [k] kill it       (kill -9 12345)
   [n] use next port (try 7879, 7880, …)
   [a] abort

   choose [k/n/a]:

Or skip the prompt with an env var, or pick a specific port up-front:

# kill the holder silently
YOGURT_PORT_POLICY=kill just release

# pick the next free port silently
YOGURT_PORT_POLICY=next just release

# pass extra args through `just release` — anything after the recipe name
just release --port 7900 --no-open

2c · Dev mode (UI development only) optional

If you're editing React components and want HMR, use just dev. It spawns Vite in the background, waits for it to bind, then starts the backend in the foreground — single terminal, Ctrl-C cleans both processes. Skip this for validation.

# both processes in one terminal — Vite on :5173, backend on :7878
just dev

# expected:
Starting Vite dev server at http://127.0.0.1:5173
  VITE v6.4.3  ready in 274 ms
Starting yogurt backend (dev mode) at http://localhost:7878

# open http://localhost:7878 (NOT 5173 — auth lives on the backend)
# Ctrl-C stops both cleanly via a trap-EXIT handler.

If you want them in two terminals (separate logs): just frontend in one, just backend in the other.

step 3

Screen Recording permission

macOS TCC — required for system-audio capture

ScreenCaptureKit's audio loopback requires the user to grant Screen Recording permission (the same one apps like Loom and OBS ask for). macOS prompts the first time you try to start a meeting.

The dialog only appears on first attempt. If you've previously denied yogurt-cli, no prompt will reappear — you'll have to flip it manually in System Settings.
  1. In the browser, click + New meeting (or whatever the empty-state CTA shows).
  2. macOS will pop the "yogurt-cli would like to record this computer's screen and audio" dialog. Click Open System Settings.
  3. System Settings opens to Privacy & Security → Screen Recording & System Audio. Toggle yogurt-cli ON.
  4. Return to the browser. Click + New meeting again — this time it should proceed.

Settings UI · API keys + provider switch

Phase 5

Open http://localhost:7878/settings. Four cards in the sidebar — Model, Transcription, Audio, General.

Release mode starts with zero providers. You'll paste your keys here on first run. Get them ready: a Deepgram key (transcript) and one LLM key (augmented notes / chat).

5a · Add your providers required

  1. Click Transcription in the sidebar. Click the Deepgram card. Paste your Deepgram key. Save. (macOS may pop a Keychain Access prompt — approve it once.)
  2. Click Model in the sidebar. Click + Add provider. Pick OpenAI from the preset list (or any OpenAI-compatible base URL). Paste your key. Save.
  3. Both should now show with masked keys (sk-•••••••••...••12) and the active one highlighted.

step 11

Local STT · the M1 Air kill criterion

Phase 8 — LOCAL-04

This is the only "blocking" gate from the autonomous run. It can only be validated on Apple Silicon — ideally M1 Air, since that's the slowest hardware Yogurt commits to supporting in v1. M3 Max is too easy.

If you're on M3 Max or M4: the bench will look healthy, but it doesn't prove LOCAL-04. Flag this in your validation summary so a real M1 Air bench can happen pre-release.
  1. Open http://localhost:7878/settings → Transcription.
  2. Click Use Local radio button on the right card. Matcha border appears.
  3. Click small.en ↓. Download dialog opens.
  4. Wait for download (~50 s on fast wifi). Pill flips to small.en ✓.
  5. In a new terminal: shasum -a 256 ~/.yogurt/models/ggml-small.en.bin.
  6. Click + New meeting. Talk for 30 s. Time the first transcript bar with a stopwatch.
  7. End meeting; confirm the transcript persisted to library.
  8. Turn wifi OFF. Close browser. Restart yogurt-cli. Start a new meeting. Talk. Transcript should still flow.
  9. Turn wifi back ON.
Report back: approved if < 3 s + offline OK, OR escalate to v2 — M1 Air bench failed at <Ns> with the measured number.

step 13

Empty & error states

Phase 7 / Plan 07-04

Two specific states ship: EmptyLibrary (no meetings yet, beautiful empty illustration) and PermissionDenied (TCC revoked, helpful "open System Settings" CTA).

  1. EmptyLibrary: in a separate test, delete every meeting from the library. The card grid should be replaced with the EmptyLibrary illustration + "Start your first meeting" CTA.
  2. PermissionDenied: in System Settings → Privacy → Screen Recording, toggle yogurt-cli OFF. Try to start a meeting in the browser. The view should swap to PermissionDenied state with an "Open System Settings" button.
  3. Re-enable Screen Recording after the test.
